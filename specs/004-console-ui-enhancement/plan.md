## Architecture Decisions

### Decision 1: Terminal Formatting Library Selection

**Options Considered**:
1. **rich** - Full-featured terminal formatting library
2. **colorama** - Lightweight color-only library
3. **blessed** - Comprehensive terminal control library

**Decision**: Use **rich** library

**Rationale**:
- Rich provides tables, panels, and styled text out-of-box (reduces custom code)
- Built-in fallback handling for non-color terminals
- Excellent Windows support without extra configuration
- Active maintenance and Python 3.13+ compatibility
- More expressive API than colorama while lighter than blessed
- Can create bordered boxes and formatted tables easily

**Trade-offs**:
- Slightly larger dependency than colorama (~1.5MB vs ~50KB)
- More features than strictly needed, but helpful for future enhancements
- Learning curve for API, but well-documented

### Decision 2: Formatting Architecture

**Options Considered**:
1. **Inline formatting** - Add rich calls directly in menu.py functions
2. **Formatter module** - Create separate module with formatting functions
3. **Theme class** - OOP approach with Theme object managing all styles

**Decision**: Use **formatter module** with pure functions

**Rationale**:
- Maintains separation between UI logic (menu.py) and presentation (formatter.py)
- Pure functions are testable and reusable
- Easier to modify styling without touching business flow
- Simpler than OOP for this scale (11 menu options)
- Follows existing project pattern (utils modules)

**Trade-offs**:
- Slightly more files than inline approach
- Function import overhead (minimal)
- Less flexible than full theme system (acceptable for Phase I)

### Decision 3: Color and Symbol Scheme

**Color Mappings**:
- **Status**: pending=cyan, in-progress=yellow, completed=green
- **Priority**: high=red, medium=yellow, low=cyan
- **Messages**: success=green, error=red, warning=yellow, info=blue
- **Highlights**: overdue=bright red, soon-due=bright yellow

**Symbol Conventions**:
- Success: ✓ (with [OK] fallback)
- Error: ✗ (with [ERROR] fallback)
- Warning: ⚠ (with [WARN] fallback)
- Info: ℹ (with [INFO] fallback)
- High priority: !!! or ⚡
- Completed: ✓ or [✓]
- In-progress: → or [>]
- Pending: ○ or [ ]

**Rationale**:
- Standard conventions match user expectations
- UTF-8 symbols with ASCII fallbacks ensure compatibility
- Distinct colors prevent confusion between status and priority
- Consistent across all screens

### API Contracts

**New Formatter Module** (src/cli/formatter.py):

```python
def format_menu_header(title: str) -> Panel:
    """Create a formatted menu header with border.

    Args:
        title: Menu title text

    Returns:
        Rich Panel object for display
    """

def format_success(message: str) -> str:
    """Format a success message with color and symbol.

    Args:
        message: Success message text

    Returns:
        Formatted string with rich markup
    """

def format_error(message: str) -> str:
    """Format an error message with color and symbol.

    Args:
        message: Error message text

    Returns:
        Formatted string with rich markup
    """

def format_warning(message: str) -> str:
    """Format a warning message with color and symbol.

    Args:
        message: Warning message text

    Returns:
        Formatted string with rich markup
    """

def format_task_display(task: Task, now: datetime) -> Panel:
    """Format a task for display in a bordered panel.

    Args:
        task: Task object to display
        now: Current datetime for overdue calculation

    Returns:
        Rich Panel with formatted task information
    """

def format_status_badge(status: str) -> str:
    """Create a colored status badge with symbol.

    Args:
        status: Task status (pending/in-progress/completed)

    Returns:
        Formatted status string with color and symbol
    """

def format_priority_badge(priority: str) -> str:
    """Create a colored priority badge with symbol.

    Args:
        priority: Task priority (high/medium/low)

    Returns:
        Formatted priority string with color and symbol
    """

def format_input_prompt(prompt: str, hint: str = "", current: str = "") -> str:
    """Format an input prompt with hints and current value.

    Args:
        prompt: Main prompt text
        hint: Format hint or examples (optional)
        current: Current value to show (optional)

    Returns:
        Formatted prompt string
    """

def get_console() -> Console:
    """Get the shared Rich Console instance.

    Returns:
        Configured Console object
    """
```

### Risk 2: Breaking Existing Functionality
**Likelihood**: Low | **Impact**: High
**Mitigation**:

- Run existing manual tests after changes
- Only modify display logic, not business logic
- Test each handler independently after modification

### Risk 3: Performance Degradation
**Likelihood**: Low | **Impact**: Low
**Mitigation**:
- Rich is optimized for console output
- In-memory app has no I/O bottlenecks
- Profile if rendering >100 tasks becomes slow
- Use lazy rendering if needed

### Risk 4: Unicode Symbol Display Issues
**Likelihood**: Medium | **Impact**: Low
**Mitigation**:
- Provide ASCII fallbacks for all symbols
- Test with various terminal encodings
- Rich handles encoding detection automatically
- Document any known symbol limitations

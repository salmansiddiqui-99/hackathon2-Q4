## Architecture Decisions

### AD-1: Data Structure - Custom Task Class

**Decision**: Use a Python dataclass for Task representation

**Options Considered**:
| Option | Pros | Cons |
|--------|------|------|
| List of dicts | Simple, quick to implement | No type safety, easy to misspell keys |
| Custom Task class | Type hints, IDE support, extensible | Slightly more code |

**Chosen**: Custom Task dataclass

**Rationale**: Aligns with constitution's emphasis on clean code and prepares for Phase II where Task will become a SQLModel. Type hints improve AI code generation accuracy.

```python
@dataclass
class Task:
    id: int
    title: str
    description: str
    status: str  # "pending" | "in-progress" | "completed"
```

### AD-2: Input Handling - Simple Menu Loop

**Decision**: Use a while loop with numbered menu options

**Options Considered**:
| Option | Pros | Cons |
|--------|------|------|
| Simple input loop | Easy to understand, minimal code | Less "professional" |
| argparse library | Standard CLI pattern | Overkill for interactive menu |
| Click/Typer | Rich CLI features | External dependency violates constraints |

**Chosen**: Simple input loop with if-elif dispatch

**Rationale**: External dependencies are prohibited for Phase I. A numbered menu with input() is sufficient and matches the spec's requirement for "console menu interface."

### AD-3: ID Management - Auto-increment Integer

**Decision**: Use simple incrementing integer starting from 1

**Options Considered**:
| Option | Pros | Cons |
|--------|------|------|
| Auto-increment integer | Simple, human-readable | IDs not reused after deletion |
| UUID | Globally unique | Overkill for in-memory, hard to type |
| Reuse deleted IDs | Efficient ID space | Complex logic, confusing UX |

**Chosen**: Auto-increment integer (never reused)

**Rationale**: Simplest approach. ID counter persists even when tasks are deleted, ensuring uniqueness within a session. Prepares for database auto-increment in Phase II.

## Feature Breakdown

### Feature 1: Add Task (P1)

**Input**: Title (required, non-empty), Description (optional)
**Output**: Confirmation message with assigned ID
**Error Cases**: Empty title → error message, task not created

**Implementation Flow**:
1. Display "Enter title:" prompt
2. Read title input, validate non-empty
3. Display "Enter description (press Enter to skip):" prompt
4. Read description (empty allowed)
5. Create Task with next available ID, status="pending"
6. Add to task list
7. Display "Task #ID created successfully"

### Feature 2: List Tasks (P1)

**Input**: None
**Output**: Formatted list of all tasks OR "No tasks" message

**Display Format**:
```
ID: 1 | Title: Buy groceries | Status: pending
   Description: Milk, eggs, bread

ID: 2 | Title: Call mom | Status: completed
   Description: (no description)
```

### Feature 3: Update Task (P2)

**Input**: Task ID, New title (Enter to skip), New description (Enter to skip)
**Output**: Confirmation message
**Error Cases**: Invalid ID → "Task not found"

**Implementation Flow**:
1. Display "Enter task ID to update:" prompt
2. Validate ID exists
3. Show current values
4. Prompt for new title (Enter keeps current)
5. Prompt for new description (Enter keeps current)
6. Apply changes
7. Display "Task #ID updated successfully"

### Feature 4: Delete Task (P2)

**Input**: Task ID
**Output**: Confirmation message
**Error Cases**: Invalid ID → "Task not found"

### Feature 5: Mark Status (P2)

**Input**: Task ID, New status
**Output**: Confirmation message
**Error Cases**: Invalid ID → "Task not found", Invalid status → list valid options

**Valid Statuses**: pending, in-progress, completed

### Feature 6: Exit (Menu)

**Input**: Select exit option from menu
**Output**: Goodbye message, program terminates

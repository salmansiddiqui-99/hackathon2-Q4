## Architecture Decisions

### AD-1: Priority Representation - String Values

**Decision**: Use string values ("high", "medium", "low") for priority

**Options Considered**:
| Option | Pros | Cons |
|--------|------|------|
| String enum | Simple, readable in output | No type enforcement |
| Integer mapping (1,2,3) | Easy sorting | Less readable in UI |
| Python Enum class | Type safety, IDE support | Adds complexity |

**Chosen**: String values with validation

**Rationale**: Simplest approach for Phase I. Strings are directly displayable in console output without conversion. Validation in Task class ensures only valid values are accepted.

```python
VALID_PRIORITIES = ("high", "medium", "low")
```

### AD-2: Tags Representation - List of Strings

**Decision**: Store tags as a Python list of lowercase strings

**Options Considered**:
| Option | Pros | Cons |
|--------|------|------|
| Comma-separated string | Simple storage | Parsing required for operations |
| List of strings | Native operations | Slightly more memory |
| Set of strings | Auto-dedup | Less predictable order |

**Chosen**: List of strings with deduplication on add

**Rationale**: Lists provide easy add/remove operations with `append()` and `remove()`. Deduplication handled explicitly when adding. Order preserved for consistent display.

### AD-3: Sorting Implementation - Dedicated Command with Persistent Preference

**Decision**: User explicitly sets sort order via menu; preference persists for session

**Options Considered**:
| Option | Pros | Cons |
|--------|------|------|
| Sort on every list | Always ordered | Hidden behavior, no control |
| Dedicated command | User control | Extra step |
| Sort flag per list call | Flexible | Complex UX |

**Chosen**: Dedicated sort command with persistent preference

**Rationale**: Gives user explicit control. Sort preference stored in TaskService and applied to all subsequent list/filter/search results until changed.

### AD-4: Search Scope - Title, Description, and Tags

**Decision**: Search keyword across all text fields

**Options Considered**:
| Option | Pros | Cons |
|--------|------|------|
| Title only | Simple, fast | Limited utility |
| Title + description | Moderate coverage | Misses tag-based search |
| Title + description + tags | Full coverage | Slightly more processing |

**Chosen**: Search across title, description, and tags

**Rationale**: Provides best usability for finding tasks. Performance impact negligible for in-memory operations with ~100 tasks.

## Extended Task Model

```python
@dataclass
class Task:
    id: int
    title: str
    description: str
    status: str = "pending"
    priority: str = "medium"  # NEW: high, medium, low
    tags: list[str] = field(default_factory=list)  # NEW: lowercase tags
    created_at: datetime = field(default_factory=datetime.now)  # NEW: for sort

    VALID_STATUSES = ("pending", "in-progress", "completed")
    VALID_PRIORITIES = ("high", "medium", "low")
```

## Feature Implementation Details

### Feature 1: Priority Assignment (US1)

**Add Task Flow** (extends existing):
1. After description prompt, add: "Enter priority (high/medium/low) [medium]:"
2. Default to "medium" if user presses Enter
3. Validate input; show error for invalid values

**Update Task Flow** (extends existing):
1. Show current priority alongside title/description
2. Add: "New priority (Enter to keep current):"
3. Apply skip-to-keep pattern

**List Display** (extends existing):
```
ID: 1 | Title: Buy groceries | Status: pending | Priority: high
   Description: Milk, eggs, bread
   Tags: [shopping, urgent]
```

### Feature 2: Tags/Categories (US2)

**Add Task Flow** (extends existing):
1. After priority prompt: "Enter tags (comma-separated, or Enter to skip):"
2. Parse input: split by comma, trim whitespace, lowercase, deduplicate
3. Store as list

**Manage Tags Menu Option** (new - option 6):
1. Prompt for task ID
2. Show current tags
3. Sub-menu: 1. Add tags, 2. Remove tag, 3. Cancel
4. Add: prompt for new tags (comma-separated)
5. Remove: show numbered list, prompt for selection

### Feature 3: Search Tasks (US3)

**Search Menu Option** (new - option 7):
1. Prompt: "Enter search keyword:"
2. If empty, show all tasks
3. Search case-insensitively across:
   - Title (substring match)
   - Description (substring match)
   - Tags (any tag contains keyword)
4. Display matching tasks in standard format
5. Show "No tasks match your search" if none found

### Feature 4: Filter Tasks (US4)

**Filter Menu Option** (new - option 8):
1. Sub-menu:
   ```
   Filter by:
   1. Status (pending/in-progress/completed)
   2. Priority (high/medium/low)
   3. Tag
   4. Clear filter (show all)
   ```
2. Prompt for filter value
3. Display filtered tasks
4. Filter persists until cleared or changed

### Feature 5: Sort Tasks (US5)

**Sort Menu Option** (new - option 9):
1. Sub-menu:
   ```
   Sort by:
   1. Priority (high → low)
   2. Title (A-Z)
   3. Creation date (oldest first)
   4. Creation date (newest first)
   ```
2. Store sort preference in TaskService
3. Apply to all subsequent list/filter/search displays
4. Show current sort order in list header
